# Set Up Hey API with GRAB

[Hey API](https://heyapi.dev) generates a typed SDK from an OpenAPI spec — one function and one set of types per endpoint. By default those functions send their requests with `fetch` or `axios`. This guide swaps the transport for grab, so the SDK you already generate gains caching, retries, rate limiting, request deduplication, mocks and a shared request log without changing a single call site.

Five steps, roughly ten minutes: install, generate, configure, call, regenerate. Every step below has a StackBlitz project you can open and edit — start with the finished one if you'd rather read the code first.

## Before you start

- **Node 18 or newer** — the generator runs `@hey-api/openapi-ts` as a child process.
- **An OpenAPI 3.x spec**, as a local file or a URL. The examples here use the public [Swagger Petstore](https://petstore3.swagger.io/api/v3/openapi.json) spec, so you can follow along without one of your own.
- **`grab-url` 1.6.22 or newer.** On 1.6.23 and later the client also reports response status, headers and parsed error payloads through grab's `onRawResponse` hook; on older versions those degrade gracefully.

## 1. Install

```bash npm2yarn
npm i grab-url api2sdk
npm i -D @hey-api/openapi-ts
```

`api2sdk` is both the runtime client the generated SDK imports and the `api2sdk` CLI that generates it. `@hey-api/openapi-ts` is Hey API's own generator — a dev dependency that never ships to production. It is optional: when it isn't installed locally the CLI falls back to `npx -y @hey-api/openapi-ts`, which refetches it on every run and leaves the generator version unpinned. Install it.

## 2. Generate the SDK

Point the CLI at your spec and an output directory:

```bash
npx api2sdk https://petstore3.swagger.io/api/v3/openapi.json ./src/client
```

That does two things: runs `openapi-ts` to generate the SDK, then rewires the generated code so its transport is grab.

| File | What's in it |
| --- | --- |
| `client.gen.ts` | The shared `client` every SDK function calls — this is where the grab transport is wired in |
| `sdk.gen.ts` | One exported function per operation: `getPetById()`, `addPet()`, … |
| `types.gen.ts` | Request and response types for every operation and schema |
| `index.ts` | Re-exports the three above |

### CLI options

| Option | Purpose |
| --- | --- |
| `-i, --input <path\|url>` | OpenAPI spec to generate from |
| `-o, --output <dir>` | Where to write the SDK — default `./src/client` |
| `-c, --client <name>` | Hey API client to generate against — default `@hey-api/client-fetch` |
| `--rewire-only` | Skip generation, rewire an SDK you already generated |
| `--no-rewire` | Generate without swapping in the grab client |
| `-h, --help` | Show usage |

Anything else is forwarded to the `openapi-ts` CLI, so `--plugins`, `--dry-run` and friends work as documented by Hey API.

### If you already have an `openapi-ts.config.ts`

Keep it. Generate with your own config, then rewire the output afterwards:

```json title="package.json"
{
  "scripts": {
    "codegen": "openapi-ts && api2sdk --rewire-only ./src/client"
  }
}
```

Rewiring handles both output shapes Hey API produces. When the client is imported as a package, imports of `@hey-api/client-fetch` (or `-axios`, `-ky`, `-next`, `-nuxt`, `-ofetch`) are repointed at `api2sdk`. When the client is bundled into `<output>/client/`, that copied implementation is replaced with a shim that re-exports the grab client. Either way, `sdk.gen.ts` and `types.gen.ts` are untouched.

### From Node instead of the CLI

```ts
import { generateFromOpenAPI } from "api2sdk";

await generateFromOpenAPI({
  input: "./openapi.yaml",
  output: "./src/client",
});
```

`rewireGeneratedClient(output)` is exported too, for the `--rewire-only` half on its own.

## 3. Configure the client

`client.gen.ts` exports a `client` that configures the whole SDK at once. Set your base URL, auth, and any grab options you want applied to every endpoint:

```ts title="src/api.ts"
import { client } from "./client/client.gen";

client.setConfig({
  baseUrl: "https://api.example.com",
  auth: () => localStorage.getItem("token"),

  // grab options — these apply to every request the SDK makes
  cache: true,
  cacheForTime: 60,
  retryAttempts: 2,
  rateLimit: 1,
  timeout: 15,
});
```

Import that module once at startup, before the first SDK call.

Prefer building the client yourself — for a second API, or one client per tenant:

```ts
import { createClient, createConfig } from "api2sdk";

const admin = createClient(createConfig({ baseUrl: "https://admin.example.com" }));

// pass it per call; the SDK falls back to the shared client when you don't
await getPetById({ path: { petId: 42 }, client: admin });
```

### grab options

Accepted client-wide in `createConfig()` / `setConfig()` and per request. Full reference: [grab options](/docs/grab-options).

| Option | Effect |
| --- | --- |
| `cache`, `cacheForTime` | Serve repeated requests from grab's frontend cache |
| `retryAttempts` | Retry failed requests |
| `rateLimit` | Minimum seconds between requests to the same path |
| `timeout` | Seconds before the request is aborted |
| `cancelOngoingIfNew`, `cancelNewIfOngoing` | Deduplicate concurrent requests to the same path |
| `debug`, `logger` | Log requests and responses |
| `unzip`, `parseDOM`, `unescapeHTML` | Opt back into grab's ZIP/HTML post-processing |
| `grab` | Use a custom instance, e.g. `grab.instance({ ... })` |

Everything Hey API's own clients accept — `auth`/`security`, `interceptors`, `bodySerializer`, `querySerializer`, `parseAs`, `responseStyle`, `throwOnError`, `responseValidator`, `responseTransformer`, `buildUrl()` — behaves exactly as it does there.

## 4. Call an endpoint

Import the generated function and go. grab options can be set per call, overriding the client-wide defaults:

```ts
import { findPetsByStatus, getPetById } from "./client/sdk.gen";

const { data: pets } = await findPetsByStatus({
  query: { status: "available" },
  cache: true,
  cacheForTime: 60,   // the next identical call skips the network
});

const { data, error, response } = await getPetById({
  path: { petId: 42 },
  retryAttempts: 3,
});

if (error) console.log(response.status, error);  // 404 { message: "Pet not found" }
```

The result is the standard Hey API shape — `{ data, error, request, response }` — or just `data` with `responseStyle: "data"`, or a thrown error with `throwOnError: true`.

### Mock any endpoint

`grab.mock` is keyed by request path relative to `baseUrl`, so an endpoint can be stubbed without a mock server and without touching the code that calls it:

```ts
import { grab } from "grab-url";

grab.mock["/pet"] = {
  method: "POST",
  response: { id: 42, name: "Rex", status: "available", photoUrls: [] },
};

const { data } = await addPet({ body: { name: "Rex", photoUrls: [] } });
// { id: 42, name: "Rex", ... } — nothing went over the wire
```

Path parameters are substituted before the lookup, so `getPetById({ path: { petId: 42 } })` matches `grab.mock["/pet/42"]`. A leading slash is optional. This is the fastest way to write tests against a generated SDK — see [testing](/docs/testing).

## 5. Regenerate when the spec changes

Commit the generated directory and regenerate it as a script, so a spec change shows up as a reviewable diff:

```json title="package.json"
{
  "scripts": {
    "codegen": "api2sdk ./openapi.yaml ./src/client"
  }
}
```

In CI, regenerate and fail the build when the output drifts from what's committed:

```yaml title=".github/workflows/codegen.yml"
- run: npm run codegen
- run: git diff --exit-code src/client
```

Nothing in `src/client` needs hand-editing after a regenerate — the rewiring is deterministic, and your configuration lives in the `setConfig()` call from step 3, not in the generated files.

## Wiring it into a framework

The SDK is plain async functions, so it drops into whatever data layer you already use.

<Tabs groupId="framework" items={['React', 'TanStack Query', 'Node']}>
<Tab value="React">

```tsx
import { useEffect, useState } from "react";
import { getPetById } from "./client/sdk.gen";
import type { Pet } from "./client/types.gen";

function PetCard({ petId }: { petId: number }) {
  const [pet, setPet] = useState<Pet | undefined>();

  useEffect(() => {
    // cancelOngoingIfNew drops the in-flight request when petId changes
    getPetById({ path: { petId }, cache: true, cancelOngoingIfNew: true })
      .then(({ data }) => setPet(data));
  }, [petId]);

  return pet ? <h2>{pet.name}</h2> : <p>Loading…</p>;
}
```

import { useQuery } from "@tanstack/react-query";

const usePet = (petId: number) =>
  useQuery({

## Troubleshooting

**Generation stalls, or fails with a network error** — the generator is resolved from your project first, and only falls back to `npx -y @hey-api/openapi-ts` when it isn't there, which needs the registry every run. Install it as a dev dependency: `npm i -D @hey-api/openapi-ts`.

**`No generated output found at …`** — `--rewire-only` was pointed at a directory that doesn't exist yet. Run the generation step first, or drop the flag.

**The SDK still imports `@hey-api/client-fetch`** — generation ran with `--no-rewire`, or the output directory moved after generating. Re-run with `api2sdk --rewire-only ./src/client`.

**A timeout or connection failure isn't throwing** — that's intentional. Transport failures come back as `{ error }`, matching grab's errors-are-data behavior. Set `throwOnError: true` if you want exceptions. HTTP error statuses behave the same as in the official clients.

**`response.status` is always 200 on failures** — the installed `grab-url` predates 1.6.23, so the client can't read the raw response. Upgrade `grab-url`; the client detects support and never sends options an older grab would turn into query parameters.

**A server-sent events endpoint doesn't work** — grab has no `sse` helper. Generate those operations against `@hey-api/client-fetch` and keep grab for the rest.
